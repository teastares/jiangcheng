# 产线求解器

用目标产物、末端台数和允许外供的物料生成两种排法。共用上游允许多台末端共用加工设备与进货口。独立供料为每台末端分别配置原料入口和完整上游，电网可以共用。每种排法输出离线 HTML、进货配额、格位 JSON、SVG、建材与额定功耗。适用的 Steam 参数表同时生成蓝图导入 TXT。 [算例总表](../blueprints/solved/README.md)

## 运行

在项目根目录使用 Python 3.10 及以上版本。安装依赖后运行以下命令。

```powershell
python -m pip install -r requirements.txt
python -m solver
```

只算指定产物时传入一个或多个算例编号。`--out` 可指向新目录，便于保留先前结果。

```powershell
python -m solver green-crystal cloth --out blueprints/my-run
python -m unittest discover -s tests -v
```

默认使用 [算例文件](../solver/examples.json) 和 [Steam 配方与建筑参数](../solver/catalog.json)。另存自己的算例 JSON 后通过 `--cases-file` 传入。自定义配方和机型通过 `--catalog` 指定。

```json
{
  "my-green-crystal": {
    "target": "绿色晶能",
    "machines": 2,
    "external": ["原木", "石头"],
    "enabled_recipes": ["木材", "木棒", "石材", "木纤维", "线", "布", "初级工具", "绿色晶能"],
    "belt_levels": [1, 2],
    "daily_supply": {"原木": 2048, "石头": 384},
    "plot": [45, 42]
  }
}
```

| 参数 | 含义 |
| --- | --- |
| `target`、`machines`、`external` | 产物、固定末端台数、允许直接补货的物料。列在 `external` 的物料从该处截断自产链。 |
| `enabled_recipes`、`belt_levels` | 存档允许的配方和物流等级。默认使用参数表中的全部条目。 |
| `rate` | 手动指定全线每分钟目标产量，支持如 `"25/3"` 的分数。省略时用末端额定满产。两种排法用同一个目标。 |
| `plot`、`power_limit_kw` | 可建矩形的宽高上限及额定电力预算。省略时不限，对应一边可用 `null` 单独取消上限。外接供电和物流在边界继续连接。 |
| `daily_supply`、`inlet_capacity` | 按物料填写 16 分钟总供给上限，或限制每个进货口的实际件数/分钟。 |
| `junction_capacity`、`underground` | 每个分合流件的吞吐上限。`underground: false` 禁用地下带。 |
| `objective`、`modes` | 按先后顺序填写优化指标。可用 `area`、`buildings`、`lines`、`materials`、`power`、`inlets`、`machines`。`modes` 可限制 `shared` 或 `separate`。 |
| `reference_start`、`orientation_search` | 默认尝试同配方、同产速的参考布局，以及机台换向、换边进货和四向线路重布。可分别设为 `false`，用于对照从头构造或固定朝向时的结果。 |
| `simulation_candidates`、`simulation_buffer_batches` | 每种排法的扩展候选、原排布候选各自的仿真名额，以及各机器端口的模拟缓存批次数。默认名额每组 32 个，缓存 4 批。两个名额组内同一候选只试一次，从排序最靠前的开始。局部压紧方案另行仿真。 |

配方表以产物为键，定义每批投入、每批产出、秒数和机型。每台设备使用一个配方，`inputs` 按朝右时端口从上到下排列。每条配方链应无循环。`virtual: true` 用于直接入账的末端。参数表的 `junction_ports` 描述分流器最多几个出口及合并器最多几个入口，取值为 `2` 或 `3`，缺省为 `2`。Steam 参数表取 `3`。各带级可通过 `underground_span` 指定两端点最大距离。Steam 一级地下带候选用样本覆盖的 2 至 5 格，其余已解锁地下带按 2 格进行规划。 [参数表](../solver/catalog.json)

## 比较方式

1. 从目标产速按精确分数倒推耗料。逐级枚举物流分组上限，用动态规划在端口顺序内选择分割点。候选分组包含集中供料、局部直连及多源多汇沿途供料。多源多汇的合计流量可以大于单带规格，逐段核对实际流量和分合流负荷。独立配置按单台末端模块重复排布。
2. 按配方依赖安排机器和干线的列位。浅支路可以靠近下游、干线可以靠近供料端，减少横越多个加工阶段的线路。SciPy 调用 HiGHS 搜索高度最小的行位，并在可行高度范围内搜索各干线纵向跨度总和较短的行位。同配方、同产速的参考布局可进入共用模式的候选。 [SciPy MILP](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html)
3. 在候选上尝试改朝向、换边进货和单物料线路重布。路径搜索沿四个方向考虑地面带和地下带，在给定的物料、流量、端点和分合流位置下计入胶囊与建材成本。可沿逐行可转折的切口删除空格或缩短直带。改变后的布局重新接电，逐格复核占位、实际端口、输送方向与负载、地下配对及相邻旁接。排序按所设优先级执行，建筑数含成品接出带，电线单列。
4. 默认按排名仿真，优先保留末 4 分钟达到目标的方案。为不同机台数、进货分组保留部分名额，并保留原排布候选的仿真名额。仿真从空线开始，按带速适配离散步长，推进物品、批次、分流轮转、缓存和堵塞。进货口持续有料，成品接出口持续清空。输出首件时间、前 16 分钟累计产量及末 4 分钟平均速率。`--no-simulation` 可只做静态检查。

## 摆放和补货

- SVG 上图为物流，下图为同坐标电网。小圆点为建筑定位格，建筑边缘的三角形指向设备朝向。合并器沿唯一出端定朝向，分流器沿唯一入端的流向定朝向。地下带虚线从入口指向出口。JSON 保存相同格位、方向、精确流量、带段坐标、线缆和接入口。
- 用浏览器离线打开 HTML，点击「导出游戏导入文本」。复制 TXT 全文并粘贴到 Steam 游戏的蓝图导入界面。自动建造前备齐页面列出的建材和建造胶囊。在游戏内指定各进货箱的物料来源。自定义机型、配方或版本时，只在兼容 `steam-25121460` 的参数表里保留 `blueprint_format` 字段。
- 在标出的格位接入足额电力。物理成品沿「出」标记的箭头接出，持续清空收货端。独立模块横向平铺时，模块之间留一列给成品转向或交接。库存和外接收货线路按实际地块布置。
- 日配额按稳态耗料乘以 16 分钟计算。每口保留精确值，分数按余料跨天调整补货量。例如每天 `640/3` 件可按 213、213、214 循环，再按箱内库存减去剩料。实际配送可用量和进货箱空间以存档为准。空线首日模拟产出见各算例。

## 验证范围

最紧凑指本次搜索候选中通过静态检查及所列仿真条件的最小面积。若命令行无仿真达标候选，报告保留静态排名第一的方案并列出仿真差距。HiGHS 的最优状态只覆盖固定列位的行位子问题。四向重布采用固定配方和分合流组的局部搜索。Steam 设备换向候选限于已有样本支持的朝向，详见研究记录。需要可重复的构造搜索时使用 `--row-time-limit 0`。旧手工双绿瓶可用 `python -m tools.benchmark_legacy_green` 回读原图并以同一模型仿真。

配方周期、建材与标称带速取自 Steam Build `25121460`。导入编码与该版本的既有样本进行逐字节回读核对。仿真的每格延迟、缓存和分合流轮转采用参数化近似。运行验收需在游戏内核对导入、满载带段、分合流吞吐及成批到料。 [数据与验证记录](research.md)
