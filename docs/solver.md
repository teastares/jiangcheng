# 产线求解器

用目标产物、末端台数和允许外供的物料生成两种排法。共用上游允许多台末端共用加工设备与进货口。独立供料为每台末端分别配置原料入口和完整上游，电网可以共用。每种排法输出离线 HTML、进货配额、格位 JSON、SVG、建材与额定功耗。适用的 Steam 参数表同时生成蓝图导入 TXT。 [算例总表](../blueprints/solved/README.md)

## 运行

在项目根目录使用 Python 3.10 及以上版本。安装依赖后运行以下命令。

```powershell
python -m pip install -r requirements.txt
python -m solver
```

只算指定产物时传入一个或多个算例编号。`--out` 可指向新目录，便于保留先前结果。

```powershell
python -m solver green-crystal cloth --out blueprints/my-run
python -m unittest discover -s tests -v
```

默认使用 [算例文件](../solver/examples.json) 和 [Steam 配方与建筑参数](../solver/catalog.json)。另存自己的算例 JSON 后通过 `--cases-file` 传入。自定义配方和机型通过 `--catalog` 指定。

```json
{
  "my-green-crystal": {
    "target": "绿色晶能",
    "machines": 2,
    "external": ["原木", "石头"],
    "enabled_recipes": ["木材", "木棒", "石材", "木纤维", "线", "布", "初级工具", "绿色晶能"],
    "belt_levels": [1, 2],
    "daily_supply": {"原木": 2048, "石头": 384},
    "plot": [45, 42]
  }
}
```

| 参数 | 含义 |
| --- | --- |
| `target`、`machines`、`external` | 产物、固定末端台数、允许直接补货的物料。列在 `external` 的物料从该处截断自产链。 |
| `enabled_recipes`、`belt_levels` | 允许的配方和物流等级。默认使用参数表中的全部条目。填 `[1, 2, 3]` 允许混用，填 `[3]` 只用三级。 |
| `rate` | 手动指定全线每分钟目标产量，支持如 `"25/3"` 的分数。省略时用末端额定满产。两种排法用同一个目标。 |
| `plot`、`power_limit_kw` | 可建矩形的宽高上限及额定电力预算。省略时不限，对应一边可用 `null` 单独取消上限。外接供电和物流在边界继续连接。 |
| `daily_supply`、`inlet_capacity` | 按物料填写 16 分钟总供给上限，或限制每个进货口的实际件数/分钟。 |
| `junction_capacity`、`underground` | 每个分合流件的吞吐上限。`underground: false` 禁用地下带。 |
| `objective`、`modes` | 按先后顺序填写优化指标。可用 `area`、`buildings`、`lines`、`materials`、`power`、`inlets`、`machines`、`transport_time`、`cadence`。`modes` 可限制 `shared` 或 `separate`。 |
| `reference_start`、`orientation_search` | 默认尝试同配方、同产速的参考布局，以及机台换向、换边进货和四向线路重布。可分别设为 `false`，用于对照从头构造或固定朝向时的结果。 |
| `simulation_candidates`、`simulation_buffer_batches` | 每种排法的扩展候选、原排布候选各自的仿真名额，以及手动设置设备缓存批数。默认名额每组 32 个。内置 Steam 参数表和 Windows 存档模式使用 3 批进料缓存与产物堆叠上限。局部压紧方案另行仿真。 |

配方表以产物为键，定义每批投入、每批产出、秒数和机型。每台设备使用一个配方，`inputs` 按朝右时端口从上到下排列。每条配方链应无循环。`virtual: true` 用于直接入账的末端。参数表的 `junction_ports` 描述分流器最多几个出口及合并器最多几个入口，取值为 `2` 或 `3`，缺省为 `2`。Steam 参数表取 `3`。各带级可通过 `underground_span` 指定两端点最大距离。Steam Build `25121460` 的一至五级地下带最大距离分别为 5、6、7、8、8 格，当前候选从 2 格开始。命令行默认参数表收录一、二级，Windows 程序使用完整解锁表。 [参数表](../solver/catalog.json) · [安装版核对](research.md)

## 比较方式

1. 使用 HiGHS 求固定配方链的产能与进货配置。令 `xᵢ` 为每分钟批数、`nᵢ` 为机器整数台数、`tᵢ` 为每批秒数。约束 `tᵢ × xᵢ ≤ 60 × nᵢ`，各口每分钟流量不超过 `nᵢ × 单口带速`，外供上限按进货口数及选填日额度计算。对每种物料，所有生产与进货之和等于消耗与成品需求之和。固定末端台数，约束额定总功率，最小化机器与单出口进货箱数量，用精确分数复核求解器解。依次比较不同带级组合，按候选物流分组用动态规划确定分割点。候选包含集中供料、局部直连及多源多汇沿途供料，允许增加并行设备换取可布线性。独立配置按单台末端模块重复排布。
2. 按配方依赖安排机器和干线的列位。浅支路可以靠近下游、干线可以靠近供料端，减少横越多个加工阶段的线路。SciPy 调用 HiGHS 搜索高度最小的行位，并在可行高度范围内搜索各干线纵向跨度总和较短的行位。同配方、同产速的参考布局可进入共用模式的候选。 [SciPy MILP](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html)
3. 在候选上尝试改朝向、换边进货和单物料线路重布。路径搜索沿四个方向选择满足实际流量和跨度的最低可用带级，比较胶囊、建材和按带速计算的运输时间。可沿逐行可转折的切口删除空格或缩短直带。改变后的布局重新接电，逐格复核占位、实际端口、输送方向与负载、相邻旁接，以及跨级端点也参与竞争的最近地下配对。排序按所设优先级执行，建筑数含成品接出带，电线单列。运输指标估算各段在途量，为各段「件/分钟 × 通过秒数 ÷ 60」之和。
4. 默认按排名仿真，优先保留末 4 分钟达到目标的方案。进货口持续有料，成品接出口持续清空。逐件跟踪运输与缓存，多种投入到齐才开工。Steam 存档模式的地下带两端各约半格，地下跨距用于核对配对和可达性。输出首件时间、前 16 分钟累计产量、末 4 分钟产速、各机计划与实际开工间隔，以及超出计划节拍的缺料与出料堵塞。`cadence` 依次比较单台最差累计停顿、各机总累计停顿、最长开工间隔的超额。`--no-simulation` 可只做静态检查。
5. 对额定负荷接近饱和或已由仿真定位的物流段，使用 HiGHS 比较当前带级与允许的更高速等级。每个带格或地下配对必须且只能选一种带级，满足流量和跨度，调整格数受限。目标比较超出 80% 的负荷、通过时间及级别代价。使用新带级之前，重新核对端口、地下带配对和产量，并确认节拍改善。带速有余量且节拍相同时，优先保留低级带。

Steam 初排、局部布线和换向均核对设施实际碰撞矩形，外接矩形包住实际机体与逻辑格。生成报告会列出本次设备的逻辑宽高、像素宽高与格距，SVG 浅色虚线标出机台和进货箱的碰撞范围。旧布局可能要增加行列以留出真实进料落点。 [设施四向尺寸表](device-footprints.md)

## 摆放和补货

- SVG 上图为物流，下图为同坐标电网。小圆点为建筑定位格，建筑边缘的三角形指向设备朝向。合并器沿唯一出端定朝向，分流器沿唯一入端的流向定朝向。地下带虚线从入口指向出口。JSON 保存相同格位、方向、精确流量、带段坐标、线缆和接入口。Steam 导入 TXT 写出后回读每个组件，HTML 与 JSON 汇总经过核对的设施方向和实际使用带级。
- 用浏览器离线打开 HTML，点击「复制蓝图」，再在 Steam 游戏的蓝图导入界面粘贴。也可通过「导出游戏导入文本」下载 TXT 并复制全文。自动建造前备齐页面列出的建材和建造胶囊。在游戏内指定各进货箱的物料来源。自定义机型、配方或版本时，只在兼容 `steam-25121460` 的参数表里保留 `blueprint_format` 字段。
- 在 HTML 页首切换「整体方向」，格位、朝向、用料和导入文本同步更新。先检验刚性旋转。因机体碰撞、端口或电线接点需要重布时，报告标明重布，且胶囊上限为原方案数量。该角度未找到合格方案时在页面提示原因。单独导出的旋转 SVG 和 TXT 带有对应的角度后缀。
- 在标出的格位接入足额电力。物理成品沿「出」标记的箭头接出，持续清空收货端。独立模块横向平铺时，模块之间留一列给成品转向或交接。库存和外接收货线路按实际地块布置。
- 日配额按稳态耗料乘以 16 分钟计算。每口保留精确值，分数按余料跨天调整补货量。例如每天 `640/3` 件可按 213、213、214 循环，再按箱内库存减去剩料。实际配送可用量和进货箱空间以存档为准。空线首日模拟产出见各算例。

## 验证范围

最紧凑指本次搜索候选中通过静态检查及所列仿真条件的最小面积。若命令行无仿真达标候选，报告列出仿真差距。HiGHS 的最优状态分别覆盖固定配方的产能配置、固定列位的行位、固定线路的带级分配。拓扑、双口替换、四向重布和动态节拍按候选搜索及仿真评价。需要关闭行位子问题时使用 `--row-time-limit 0`。旧手工双绿瓶可用 `python -m tools.benchmark_legacy_green` 回读原图并仿真。

配方周期、建材与标称带速取自 Steam Build `25121460`。导入编码与该版本的既有样本进行逐字节回读核对。仿真的每格延迟、缓存和分合流轮转采用参数化近似。运行验收需在游戏内核对导入、满载带段、分合流吞吐及成批到料。 [数据与验证记录](research.md)
